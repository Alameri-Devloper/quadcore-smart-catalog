# Product Media Workflow Orchestration | تنسيق دورة عمل وسائط المنتج

## Boundary | الحدود

Product Media workflow orchestration is an independent Catalog module. It never changes Product publication state: a Published Product remains Published when it has no images or when any Media operation fails. Product Entry, UI, public pages, and Task 3.14.9 are outside this module. | يعمل تنسيق وسائط المنتج كوحدة مستقلة داخل الكتالوج، ولا يغير حالة نشر المنتج؛ يبقى المنتج المنشور منشورًا عند غياب الصور أو فشل أي عملية وسائط، بينما تبقى واجهة إدخال المنتج والواجهات العامة والمهمة 3.14.9 خارج هذه الوحدة.

## Reused foundation | الأساس المعاد استخدامه

Task 3.14.9-B composes a Product Entry Infrastructure adapter over these Application use cases. The adapter does not merge the boundaries or give Product Entry authority over canonical Media state. | تركب المهمة 3.14.9-B محولاً في بنية Product Entry فوق حالات الاستخدام هذه دون دمج الحدود أو منح Product Entry سلطة على حالة الوسائط الأساسية.

Task 3.14.9-B-R1 permits a Pending-operation resume command to carry the durable raw source SHA-256 for already completed source operations instead of their bytes. Product Media validates any supplied hash against supplied bytes, reconstructs the unchanged request fingerprint, and executes only durable Pending operations; retained-Staging retries still use the dedicated retry use case. | تسمح المهمة 3.14.9-B-R1 لأمر استئناف عملية معلقة بحمل بصمة SHA-256 الخام المحفوظة للعمليات المكتملة بدلاً من بايتاتها. تتحقق Product Media من توافق البصمة مع أي بايتات مرسلة، وتعيد بناء بصمة الطلب دون تغيير، ولا تنفذ إلا العمليات المعلقة، بينما تستخدم إعادة محاولة المصدر المرحلي حالة الاستخدام المخصصة للإعادة.

The workflow reuses `ProductMediaRoot`, canonical final/Staging/Trash keys, `ProductImageProcessor`, `ProductMediaStoragePort`, `LocalProductMediaStorageAdapter`, checksum validation, no-clobber publication, replacement restoration, Trash movement, and the PostgreSQL Product/Media-root repositories. Application code contains no filesystem paths or low-level filesystem operations. | تعيد الدورة استخدام جذر الوسائط والمفاتيح المنمطة للملفات النهائية والمؤقتة وسلة المحذوفات ومعالج الصور ومنفذ التخزين ومحول التخزين المحلي والتحقق من البصمة والنشر دون استبدال والاستعادة وسجل PostgreSQL، ولا تحتوي طبقة التطبيق على عمليات نظام ملفات منخفضة المستوى.

## Workflow and operation lifecycle | دورة العمل والعمليات

Workflows derive `Pending`, `InProgress`, `Completed`, `PartiallyCompleted`, `Failed`, `ReconciliationRequired`, or `Cancelled` deterministically from their operations. Add and Replace are staged independently and execute before Remove. Reorder and SetCover mutate Metadata only. Completed operations are never replayed. | تُشتق حالة الدورة حتميًا من حالات العمليات، وتُجهز الإضافة والاستبدال بصورة مستقلة وتنفذان قبل الإزالة، بينما يغير الترتيب والغلاف البيانات الوصفية فقط، ولا تعاد العمليات المكتملة.

## Partial success and compensation | النجاح الجزئي والتعويض

Each successful operation remains complete when another fails. Replacement failure preserves the former published object and Metadata. Removal moves the object to Trash. If a filesystem effect succeeds but the database transaction fails, supported operation-scoped compensation runs; failure to restore a known state produces `ReconciliationRequired` and blocks automatic cleanup or retry. | تبقى كل عملية ناجحة مكتملة عند فشل غيرها، ويحافظ فشل الاستبدال على الملف السابق وبياناته، وتنقل الإزالة الملف إلى السلة، وعند نجاح أثر التخزين وفشل المعاملة تنفذ آلية التعويض المدعومة، ويؤدي فشل استعادة حالة معلومة إلى حالة تتطلب المصالحة وتمنع التنظيف أو الإعادة التلقائية.

## Cover and order | الغلاف والترتيب

Cover priority is: successfully selected Media, existing valid cover, then `displayOrder`, `createdAt`, and `mediaId`. If no published item remains, the cover is absent. Reorder never changes `storageArtifactKey`; physical gallery filenames remain stable. | أولوية الغلاف هي الوسيط المحدد الناجح ثم الغلاف الحالي الصالح ثم ترتيب العرض ووقت الإنشاء ومعرف الوسيط، ويزال الغلاف عند عدم بقاء وسائط منشورة، ولا يغير ترتيب العرض مفتاح التخزين أو اسم الملف الفعلي.

## Retry, retention, cancellation, and cleanup | الإعادة والاحتفاظ والإلغاء والتنظيف

Retry is manual only. Attempts are numerically unlimited during the original 14-day Staging window, but one atomic active claim is allowed per operation. Attempts never extend `expiresAt`. Missing or expired Staging becomes `SourceUnavailable` with `retryAllowed=false` and `requiresNewSource=true`. Cancellation affects only incomplete operations and discards only their owned Staging key. Cleanup is Workspace-scoped, repeatable, and ignores `ReconciliationRequired` and unknown residue. No scheduler or Background Worker exists in V1. | الإعادة يدوية فقط وعدد المحاولات غير محدود خلال نافذة الاحتفاظ الأصلية ذات الأربعة عشر يومًا مع سماح مطالبة نشطة ذرية واحدة لكل عملية، ولا تمدد المحاولات وقت الانتهاء. يصبح المصدر المفقود أو المنتهي غير متاح ويتطلب مصدرًا جديدًا. يؤثر الإلغاء على العمليات غير المكتملة وينظف مفتاحها المملوك فقط، والتنظيف مقيد بمساحة العمل وقابل للتكرار ويتجاهل حالات المصالحة والبقايا المجهولة، ولا يوجد مجدول أو عامل خلفي في الإصدار الأول.

Cancellation and cleanup use one focused terminal-establishment protocol after a confirmed Staging deletion. A Workflow-version conflict reloads the exact Workspace-scoped Workflow once, inspects the exact operation, accepts only a compatible terminal truth, and otherwise retries one transition with the reloaded version without replaying the filesystem effect. Cleanup returns a typed result containing `cleanedCount` plus operation-scoped reconciliation entries; only durable `SourceUnavailable` truth is counted. A missing immutable root produces a reconciliation entry without deriving or deleting any path. | يستخدم الإلغاء والتنظيف بروتوكولًا واحدًا لإثبات الحالة النهائية بعد تأكيد حذف Staging. عند تعارض إصدار الدورة تُعاد قراءة الدورة نفسها داخل مساحة العمل مرة واحدة وتُفحص العملية المحددة، ولا تُقبل إلا حقيقة نهائية متوافقة، وإلا تُحاول نقلة واحدة بالإصدار المعاد تحميله دون إعادة أثر نظام الملفات. يعيد التنظيف نتيجة نمطية تحتوي عدد العناصر المنظفة وإدخالات المصالحة لكل عملية، ولا تُحسب إلا حالة `SourceUnavailable` الدائمة. ويؤدي غياب الجذر الثابت إلى إدخال مصالحة دون اشتقاق أو حذف أي مسار.

Storage probes distinguish confirmed absence from probe failure. Confirmed missing Staging becomes `SourceUnavailable`; a known probe failure remains `ProductMediaStorageFailed`; ambiguous probe state becomes `ReconciliationRequired`. For Replace and Remove, confirmed absence of a canonical final object is metadata/filesystem divergence and becomes `ReconciliationRequired`. | تميز فحوص التخزين بين الغياب المؤكد وفشل الفحص. يصبح غياب Staging المؤكد `SourceUnavailable`، ويبقى فشل الفحص المعروف `ProductMediaStorageFailed`، وتصبح حالة الفحص الغامضة `ReconciliationRequired`. وفي الاستبدال والإزالة يمثل غياب الملف النهائي المعتمد اختلافًا بين البيانات الوصفية ونظام الملفات ويتطلب المصالحة.

## Persistence and tenancy | الحفظ وتعدد المستأجرين

PostgreSQL stores workflows, operations, canonical Media state, and Media items using Workspace-composite identities and foreign keys. The workflow idempotency key is unique per Workspace. Workflow version and Media revision enforce optimistic concurrency. A cover foreign key can reference only a Media item owned by the same Workspace and Product. Only trusted actor context supplies `workspaceId`, and the existing Product repository verifies Product ownership before execution. | يحفظ PostgreSQL الدورات والعمليات وحالة الوسائط وعناصرها بمفاتيح وعلاقات مركبة تتضمن مساحة العمل، ويكون مفتاح منع التكرار فريدًا داخلها. يطبق إصدار الدورة ومراجعة الوسائط التعارض التفاؤلي، ولا يشير الغلاف إلا إلى وسيط للمنتج ومساحة العمل نفسيهما. تأتي هوية مساحة العمل من سياق الممثل الموثوق فقط ويتحقق مستودع المنتج من الملكية قبل التنفيذ.

## R5 durability and typed outcomes | متانة R5 والنتائج النمطية

`ProductMediaOperationId` is the single identifier policy at command validation, Staging/Trash key creation, and persisted rehydration. It permits 1–80 lowercase ASCII characters, starts with a letter or digit, and rejects unsafe or reserved Windows and media-namespace names before authorization, Product lookup, root lookup, workflow creation, or storage access. | تمثل `ProductMediaOperationId` سياسة المعرّف الوحيدة عند التحقق من الأمر وإنشاء مفاتيح التجهيز والسلة وإعادة بناء البيانات المحفوظة. تسمح من 1 إلى 80 محرفاً لاتينياً صغيراً، وتبدأ بحرف أو رقم، وترفض الأسماء غير الآمنة أو المحجوزة في Windows ومساحات أسماء الوسائط قبل التفويض أو قراءة المنتج أو الجذر أو إنشاء دورة العمل أو الوصول إلى التخزين.

After a successful filesystem Stage, a focused Workspace-scoped optimistic repository transition atomically writes the complete Staged metadata and workflow version without changing canonical Media rows or the Media revision. A version conflict reloads once. Exact compatible Staged truth is accepted; a still-Pending operation gets one transition retry using the reloaded version, without staging again. If durable Staged truth cannot be established, only the exact operation-owned key is discarded: confirmed deletion or absence establishes `SourceUnavailable`, while ambiguous deletion establishes `ReconciliationRequired`. A Stage cleanup unlink failure is a typed partial-operation ambiguity. | بعد نجاح التجهيز في نظام الملفات، يسجل انتقال تفاؤلي مخصص ومقيّد بمساحة العمل جميع بيانات `Staged` وإصدار دورة العمل ذرياً من دون تغيير صفوف الوسائط المعتمدة أو مراجعتها. عند تعارض الإصدار تعاد القراءة مرة واحدة؛ تقبل حقيقة `Staged` المتطابقة، وتحصل العملية التي ما زالت `Pending` على محاولة انتقال واحدة بالإصدار المعاد تحميله من دون إعادة التجهيز. إذا تعذر إثبات الحقيقة الدائمة، يحذف مفتاح العملية المملوك فقط: الحذف المؤكد أو الغياب يثبت `SourceUnavailable`، والغموض يثبت `ReconciliationRequired`. وفشل حذف ملف جزئي أثناء التجهيز غموض نمطي لعملية جزئية.

Initial and retry publication use the same storage-failure policy. Missing Add/Replace temporary input becomes `SourceUnavailable`; missing canonical Replace/Remove data, Trash conflicts, allocated-final target conflicts, replacement-restoration failures, unsafe keys, and partial operations require reconciliation. Other failures remain retryable only when the policy explicitly classifies them as safe. Cancelling `InProgress` returns `ProductMediaOperationAlreadyInProgress` before storage or persistence mutation. | يستخدم النشر الأولي وإعادة المحاولة سياسة واحدة لتصنيف فشل التخزين. يصبح غياب المصدر المؤقت للإضافة أو الاستبدال `SourceUnavailable`، بينما يتطلب غياب الملف المعتمد للاستبدال أو الإزالة وتعارض السلة أو الهدف النهائي المحجوز وفشل استعادة الاستبدال والمفاتيح غير الآمنة والعمليات الجزئية حالة `ReconciliationRequired`. ولا يبقى أي فشل قابلاً للإعادة إلا إذا صنفته السياسة صراحةً على أنه آمن. ويرفض إلغاء عملية `InProgress` بالرمز `ProductMediaOperationAlreadyInProgress` قبل أي تعديل في التخزين أو الحفظ.

Cleanup returns `scannedCount`, `cleanedCount`, `reconciliationRequiredCount`, `skippedCount`, and deterministic operation-scoped `outcomes`. `scannedCount` equals the number of outcomes for operations returned inside Workspace-owned candidate workflows, including ineligible siblings; foreign Workspace workflows are discarded before counting. `cleanedCount` increases only for durable `SourceUnavailable`; reconciliation and skipped counts equal outcomes of those respective types. Outcomes expose only Workspace, workflow, and operation identities plus stable reason/status codes. | يعيد التنظيف `scannedCount` و`cleanedCount` و`reconciliationRequiredCount` و`skippedCount` ونتائج حتمية على مستوى العملية. يساوي `scannedCount` عدد النتائج لعمليات دورات العمل المرشحة المملوكة لمساحة العمل، بما فيها العمليات الشقيقة غير المؤهلة، وتستبعد دورات العمل التابعة لمساحات أخرى قبل العد. لا يزيد `cleanedCount` إلا عند إثبات `SourceUnavailable` دائماً، ويساوي عدادا المصالحة والتخطي عدد النتائج من النوع المقابل. ولا تكشف النتائج إلا هويات مساحة العمل ودورة العمل والعملية مع رموز سبب وحالة ثابتة.

## V1 limitations | قيود الإصدار الأول

There is no automatic retry, scheduler, permanent Trash deletion, object-storage adapter, branch-specific Media, Product Entry integration, or distributed transaction guarantee. Reconciliation is an explicit operational action. | لا توجد إعادة تلقائية أو جدولة أو حذف دائم للسلة أو تخزين كائنات أو وسائط خاصة بالفروع أو تكامل مع إدخال المنتج أو ضمان معاملة موزعة، وتبقى المصالحة إجراءً تشغيليًا صريحًا.
